# Career-Ops-GUI-cn 使用手册

你的本地 AI 求职工作台。从发现岗位、评估匹配度、生成简历，到追踪投递、准备面试 -- 一站式管理整个求职流程。

所有数据保存在你的电脑上，不上传云端。

> **阅读提示：** 本手册用以下标签区分每个功能的驱动方式：
>
> - `[手动]` -- 需要你亲自操作或录入
> - `[AI 驱动]` -- 由 AI 自动完成，你只需点击触发
> - `[自动]` -- 系统自动处理，无需 AI 参与

## 这个工具能帮你做什么

| 能力 | 驱动方式 | 说明 |
| --- | --- | --- |
| 维护目标公司库 | `[手动]` | 你手动添加和管理目标公司 |
| 批量发现岗位 | `[手动]` 触发，`[自动]` 抓取 | 你选公司和关键词，系统自动从招聘站抓取结果 |
| AI 分析 JD 质量和匹配度 | `[AI 驱动]` | AI 从匹配度、薪资、文化等维度打 1-5 分 |
| AI 优化岗位描述 | `[AI 驱动]` | AI 重新整理 JD，提取关键信息 |
| 生成定制 PDF 简历 | `[手动]` 选岗位，`[自动]` 生成 | 你选目标岗位，系统自动排版生成 PDF |
| 追踪投递状态 | `[手动]` | 你手动更新每份投递的状态和备注 |

| 生成面试准备材料 | `[AI 驱动]` | AI 基于岗位和简历生成技术题、项目题、行为题 |

## 安装与启动

### 你需要准备什么

- Node.js 18 或更高版本（[下载地址](https://nodejs.org)）
- Windows 10/11（也支持 macOS / Linux）
- Chrome 或 Edge 浏览器（推荐，用于生成 PDF 简历）

### 方式一：双击启动（推荐）

Windows 用户直接双击项目根目录的 `start-gui.bat`，它会自动完成：

1. 检查 Node.js 是否已安装
2. 运行环境检查并安装所有依赖 `[自动]`
3. 检测本机浏览器 `[自动]`
4. 启动后端服务和前端页面
5. 自动打开浏览器

首次启动可能需要几分钟安装依赖，请耐心等待。

启动完成后，浏览器会自动打开 `http://localhost:5173`，这就是你的求职工作台。

另外两个批处理脚本也很实用：

- `restart-gui.bat` -- 页面打不开或热更新异常时，双击重启
- `stop-gui.bat` -- 彻底关闭项目，释放端口

### 方式二：命令行启动

如果你习惯用终端：

```bash
# 进入项目目录
cd career-ops-gui-cn

# 运行环境检查（首次使用必须执行）
npm run doctor

# 启动后端（终端 1）
npm run api

# 启动前端（终端 2）
npm run gui:dev
```

打开浏览器访问 `http://localhost:5173`。

## 第一次使用：5 分钟上手

### 第 1 步：确认环境正常 `[自动]`

打开应用后，你会看到「求职工作台」首页。点击「运行检查并安装依赖」按钮，等待所有检查项变为绿色对勾。

健康检查会 `[自动]` 完成以下事项：

- 安装根目录和前端的 npm 依赖
- 检测本机 Chrome / Edge 浏览器
- 缺失浏览器时自动安装 Playwright Chromium
- 自动生成缺失的配置模板文件（`cv.md`、`config/profile.yml`、`portals.yml`）

如果有红色叉号，按照提示修复即可。

### 第 2 步：配置 AI 接口 `[手动]`

进入左侧菜单的「设置」页面，`[手动]` 配置至少一个 AI 提供商：

- **DeepSeek** -- 填入你的 API Key，Base URL 和模型一般不需要修改
- **豆包 / 火山方舟** -- 填入火山方舟的 API Key 和 Endpoint ID

API Key 只保存在你本机的 `.env` 文件中，不会上传到任何地方。

> 没有 API Key？去 [DeepSeek 开放平台](https://platform.deepseek.com/) 注册即可，新用户通常有免费额度。

### 第 3 步：录入你的简历信息 `[手动]`

进入「首次使用」页面，`[手动]` 按区块填写：

- 基本信息（姓名、联系方式、GitHub 等）
- 教育背景
- 项目经历
- 工作 / 实习经历
- 技能关键词
- 求职目标（目标岗位、城市、企业类型）

每个区块可以独立保存，不用一次填完。

**如果你已经有整理好的 JSON 数据**，可以直接导入。项目根目录的 `Template.JSON` 文件是模板，按格式填好后在「岗位发现」页面导入即可。

### 第 4 步：开始使用

信息录入完成后，你就可以进入核心工作流了。推荐按这个顺序操作：

```text
岗位发现 -> 候选区筛选 -> 岗位列表（提取 JD / AI 评分）-> 简历生成 -> 投递追踪 -> 面试准备
```

下面逐个介绍每个页面的用法。

## 页面功能详解

### 工作台（Dashboard）

进入应用后的第一个页面。这里展示你的求职全局状态：

- 已发现岗位总数、有效岗位数、推荐投递数 `[自动]` 统计
- 待跟进的投递记录 `[自动]` 统计
- 项目健康状态 `[自动]` 检测
- 最近发现的岗位和投递记录 `[自动]` 展示

适合每天打开先看一眼，了解当前求职进展。

### 首次使用（Onboarding）

`[手动]` 录入你的简历信息。页面按区块折叠展示，包括：

- 个人信息
- 教育背景（支持多段）
- 项目经历（支持多段）
- 工作 / 实习经历（支持多段）
- 技能关键词
- 求职目标

日期选择支持年月输入（如 `2024-07`），仍在进行中的经历可以填 `present`。

这个页面适合第一次使用时快速录入基础资料。后续可以在「简历生成」页面继续完善。

### 公司库（Companies）

`[手动]` 维护你关注的目标公司。每家公司可以配置：

- 公司名称和别名
- 行业标签
- 岗位搜索关键词（如「嵌入式」「PLC」）
- 屏蔽关键词（如「销售」「客服」）
- 工作地点
- 公司来源类型
- 是否启用

**使用建议：** 如果你的求职策略是「先定公司，再找岗位」，优先维护这个页面。后续「岗位发现」会基于公司库来搜索。

### 岗位发现（Discovery）

从公司库或关键词出发，搜索并导入候选岗位。

| 操作 | 驱动方式 | 说明 |
| --- | --- | --- |
| 选公司、输入关键词 | `[手动]` | 你决定搜什么 |
| 从招聘站抓取岗位列表 | `[自动]` | 系统自动访问招聘页面提取信息 |
| 粘贴 JSON 批量导入 | `[手动]` | 你准备好数据后粘贴 |
| 粘贴岗位 URL 导入 | `[手动]` | 你提供链接，系统自动抓取内容 |

搜索结果会先进入「候选区」，你确认后再转入正式岗位列表。

**推荐流程：** 先 `[手动]` 维护公司库 -> 再到发现页 `[手动]` 触发搜索 -> 系统 `[自动]` 抓取结果 -> 你 `[手动]` 筛选后转入岗位列表。

### 候选区（Candidates）

`[手动]` 筛选搜索结果中信息不完整、待确认的岗位。相当于一个「缓冲区」。

你可以在这里：

- `[手动]` 批量勾选岗位
- `[手动]` 将确认有价值的岗位「晋升」到正式岗位列表
- `[手动]` 删除不需要的岗位

避免把所有粗糙的搜索结果直接塞进正式岗位池。

### 岗位列表（Jobs）

**这是你使用频率最高的页面。** 所有正式岗位在这里管理和处理。

**导入岗位的方式（均为 `[手动]` 触发）：**

- 粘贴岗位 URL
- 手动输入 JD 文本
- 从候选区转入
- 批量导入 JSON

**对每个岗位可以执行的操作：**

| 操作 | 驱动方式 | 说明 |
| --- | --- | --- |
| 提取 JD | `[手动]` 触发，`[自动]` 抓取 | 你点击按钮，系统自动从 URL 抓取 JD 正文 |
| AI 优化 JD | `[手动]` 触发，`[AI 驱动]` | 你点击按钮，AI 自动重新整理 JD 结构和关键信息 |
| AI 评分 | `[手动]` 触发，`[AI 驱动]` | 你点击按钮，AI 从多维度打 1-5 分并生成评估报告 |
| 生成简历 | `[手动]` 选择岗位 | 跳转到简历生成页 |
| 加入追踪 | `[手动]` | 将岗位加入投递追踪列表 |
| 面试准备 | `[手动]` 触发，`[AI 驱动]` | 跳转到面试准备页，AI 生成题目 |

**支持批量操作：** 勾选多个岗位后可以批量删除、批量提取 JD、批量优化、批量评分。批量操作中每条岗位的处理逻辑与单条相同。

**AI 评分标准（1-5 分）：**

- 4.5 分以上 -- 强烈推荐，立即投递
- 4.0 - 4.4 分 -- 值得投递
- 3.5 - 3.9 分 -- 一般，有特别原因才投
- 3.5 分以下 -- 不推荐

**推荐操作顺序：** `[手动]` 导入岗位 -> `[手动]` 点击提取 JD（`[自动]` 抓取） -> `[手动]` 点击 AI 优化（`[AI 驱动]`） -> `[手动]` 点击 AI 评分（`[AI 驱动]`） -> 根据评分 `[手动]` 决定是否继续。

### 简历生成（Resume Builder）

在这里维护你的简历素材，并针对目标岗位生成 PDF。

| 操作 | 驱动方式 | 说明 |
| --- | --- | --- |
| 编辑个人信息 | `[手动]` | 你填写姓名、联系方式等 |
| 管理教育/经历/项目模块 | `[手动]` | 你录入和编辑每段经历 |
| 调整模块顺序和开关 | `[手动]` | 你决定简历显示哪些模块 |
| 上传个人照片 | `[手动]` | 你上传照片文件 |
| 预览简历 | `[自动]` | 系统实时渲染预览 |
| 生成 PDF 简历 | `[手动]` 选岗位，`[自动]` 生成 | 你选目标岗位，系统自动排版输出 PDF |

**使用方式：**

1. `[手动]` 把你的教育、项目、工作经历录入完整
2. `[手动]` 检查各模块是否已启用
3. `[手动]` 选择目标岗位，点击生成简历
4. 系统 `[自动]` 排版生成 PDF，保存在 `output/` 目录

如果你经常需要对不同岗位做差异化简历，这个页面会是你的核心工作区。

### 投递追踪（Tracker）

`[手动]` 管理你已经投递或决定投递的岗位。

**投递状态（全部需要 `[手动]` 更新）：**

| 状态 | 含义 |
| --- | --- |
| Evaluated | 已评估 |
| Applied | 已投递 |
| Responded | 已回复 |
| Interview | 面试中 |
| Offer | 已录取 |
| Rejected | 已拒绝 |
| Discarded | 已放弃 |

每次投递、沟通、面试后，`[手动]` 回来更新状态。用备注 `[手动]` 记录关键信息，比如投递渠道、联系人、面试轮次。

**使用建议：** 只把真正值得推进的岗位加入追踪，保持列表干净。

### 跟进提醒（Follow-ups）

`[自动]` 基于投递记录生成跟进节奏建议。你不需要手动设置提醒，系统会根据投递状态和时间自动判断。

按紧急程度分类：

| 级别 | 含义 | 你需要做什么 |
| --- | --- | --- |
| 紧急 | 需要立即跟进 | `[手动]` 发送跟进消息 |
| 逾期 | 已超过建议跟进时间 | `[手动]` 决定是否继续跟进 |
| 等待中 | 还在合理等待范围内 | 暂时不用操作 |
| 已冷却 | 长时间无回应 | `[手动]` 决定是否放弃 |

标记已发送和记录消息内容需要 `[手动]` 操作。

### 面试准备（Interview Prep）

`[手动]` 选择岗位并触发，`[AI 驱动]` 生成完整面试材料。

**生成内容（全部由 AI 自动完成）：**

- 匹配度分析 -- AI 分析你的简历与岗位的匹配情况
- 技术面试题 -- AI 根据岗位 JD 生成
- 项目深挖题 -- AI 针对你简历中的项目经历生成
- 行为面试题 -- AI 根据岗位要求生成
- 项目讲法建议 -- AI 建议如何讲述你的项目

你 `[手动]` 勾选已练习的题目来跟踪准备进度。可以 `[手动]` 导出为 Markdown 文件。

**前提条件：** 岗位已完成 AI 评分，简历信息较完整。

**使用建议：** 这个功能适合重点岗位深度准备，不需要每个岗位都生成。对最想拿下的 3-5 个岗位用好就够了。

### 设置（Settings）

| 操作 | 驱动方式 | 说明 |
| --- | --- | --- |
| 运行健康检查 | `[手动]` 触发，`[自动]` 执行 | 检测环境并自动安装缺失依赖 |
| 配置 DeepSeek API Key | `[手动]` | 填入你的 Key |
| 配置豆包 API Key | `[手动]` | 填入你的 Key |
| 清除 API Key | `[手动]` | 删除已保存的 Key |
| 验证配置 | `[手动]` 触发，`[自动]` 检查 | 检查数据文件一致性 |
| 同步检查 | `[手动]` 触发，`[自动]` 检查 | 检查简历和配置文件同步状态 |

如果 AI 评分、面试准备等功能突然不工作，先回到这里检查 API 配置。

## 典型使用场景

### 场景一：从零开始找工作

1. 双击 `start-gui.bat` 启动项目
2. `[手动]` 在设置页配置 AI API
3. `[手动]` 在首次使用向导录入简历信息
4. `[手动]` 在公司库添加目标公司
5. `[手动]` 在岗位发现页触发搜索，系统 `[自动]` 抓取结果
6. `[手动]` 在候选区筛选后转入岗位列表
7. `[手动]` 触发批量提取 JD（`[自动]`）、AI 评分（`[AI 驱动]`）
8. `[手动]` 对高分岗位生成简历 PDF（`[自动]` 排版）
9. `[手动]` 加入投递追踪，后续 `[手动]` 更新状态
10. `[手动]` 对重点岗位触发面试准备（`[AI 驱动]` 生成）

### 场景二：已有明确岗位 JD

1. `[手动]` 在岗位列表粘贴 URL 或 JD 文本
2. `[手动]` 触发提取 JD -> AI 优化 -> AI 评分
3. `[手动]` 生成简历 PDF
4. `[手动]` 加入投递追踪
5. 面试前 `[手动]` 触发生成面试准备材料

### 场景三：日常投递管理

1. 打开工作台 `[自动]` 查看全局状态
2. `[手动]` 在投递追踪页更新已投岗位的状态
3. 查看跟进提醒页 `[自动]` 生成的建议，`[手动]` 执行跟进
4. 对新发现的岗位重复「提取 -> 评分 -> 简历 -> 投递」流程

## JSON 简历模板说明

如果你不想在界面上逐项填写，可以 `[手动]` 准备一个 JSON 文件后导入。项目根目录的 `Template.JSON` 是标准模板。

JSON 顶层包含两个对象：

```json
{
  "candidate": {
    "full_name": "你的姓名",
    "summary": "一句话定位",
    "skills": ["技能1", "技能2"],
    "education": [...],
    "experience": [...],
    "projects": [...]
  },
  "target": {
    "roles": ["目标岗位"],
    "cities": ["目标城市"],
    "levels": ["校招/应届"],
    "enterprise_types": ["不限"],
    "positive_keywords": ["关键词"],
    "negative_keywords": ["排除词"],
    "companies": ["目标公司"]
  }
}
```

**填写提示：**

- 日期统一用 `YYYY-MM` 格式，如 `2024-07`
- 仍在进行中的经历，`end_date` 写 `present`
- `skills`、`roles`、`cities` 等字段写成数组效果最好，写成逗号分隔的字符串也能自动识别
- 教育经历支持 `school`、`degree`、`major`、`start_date`、`end_date`、`gpa`、`description`
- 项目经历支持 `name`、`role`、`start_date`、`end_date`、`description`、`tech_stack`

## 常见问题

### 启动后页面打不开

- 确认两个终端都在运行（后端 `localhost:3001`，前端 `localhost:5173`）
- 双击 `restart-gui.bat` 重启
- 检查 3001 和 5173 端口是否被其他程序占用

### AI 评分没有反应

- 进入「设置」页 `[手动]` 检查 API Key 是否已配置
- 确认 API Key 有效且有余额
- 检查网络是否能访问 DeepSeek 或火山方舟的 API

### PDF 生成失败

- 确认已安装 Chrome 或 Edge 浏览器
- `[手动]` 运行 `npm run doctor` 检查浏览器依赖
- 如果本机没有浏览器，健康检查会 `[自动]` 安装 Playwright Chromium

### npm install 很慢或失败

健康检查默认使用阿里云镜像源，如果仍然失败，会 `[自动]` 尝试腾讯源和官方源。你也可以手动指定：

```bash
npm install --registry=https://registry.npmmirror.com/
```

### 数据保存在哪里

所有数据都在项目本地目录：

| 内容 | 路径 |
| --- | --- |
| 岗位、公司、候选区 | `data/job-radar/` |
| 投递记录 | `data/applications.md` |
| 跟进记录 | `data/follow-ups.md` |
| 评分报告 | `reports/` |
| 导出的 PDF 简历 | `output/` |
| 面试准备文件 | `interview-prep/` |
| AI API 配置 | `.env` |
